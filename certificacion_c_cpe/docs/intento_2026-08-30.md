## Incidencias encontradas y su resolución (importante para un futuro intento)

1. **Nombres de archivo con espacio inicial al crearlos vía "New File" en el explorador de
   BAS.** Pegar contenido directamente en un archivo recién creado por el diálogo gráfico de
   BAS puede introducir un espacio al principio del nombre real del archivo (invisible en el
   Explorer, visible con `ls -la`: `' schema.cds'` en vez de `schema.cds`). Causaba errores
   como `Can't find local module '../db/schema'` o CSVs no cargados en silencio. **Solución
   fiable:** crear el archivo vacío con `touch nombre.ext` desde la terminal, y solo después
   abrirlo por doble clic en el Explorer para pegar el contenido — así el nombre real nunca
   lleva espacios.
2. **Heredoc multilínea (`cat > archivo << 'EOF' ... EOF`) pegado en la terminal web de BAS no
   siempre se ejecuta correctamente** — puede quedarse "colgado" sin crear el archivo. Si pasa,
   usar el método del punto 1 en su lugar.
3. **Indentación YAML rota en `mta.yaml` al editar con el editor gráfico**: pegar un bloque ya
   indentado sobre una posición con auto-indentado activo duplica espacios y genera
   `yaml: line X: mapping values are not allowed in this context` en `mbt build`. **Solución
   fiable:** regenerar el archivo completo vía `cat > mta.yaml << 'EOF' ... EOF` en la terminal
   en vez de editar en el editor gráfico.
4. **Login de Cloud Foundry — API endpoint incorrecto por defecto.** El BTP Cockpit mostraba
   `https://api.cf.eu10.hana.ondemand.com` como sugerencia en el wizard gráfico de login de
   BAS, pero el endpoint real de la subcuenta del examen era
   **`https://api.cf.eu10-005.hana.ondemand.com`** (con sufijo `-005`). Con el endpoint
   incorrecto, `cf orgs` devolvía "No orgs found" a pesar de que el usuario sí era miembro de
   la organización (confirmado en Cockpit). **Cómo verificar el endpoint correcto:** BTP
   Cockpit → Subcuenta → Resumen → pestaña "Entorno Cloud Foundry" → campo "API Endpoint" (y de
   paso el "Org Name" exacto, que puede llevar espacios raros, ej.
   `SAP EXAM C_CPE _c-cpe-cpe-a006656-cf-eu10-sd`).
5. **`cds.requires.auth: "none"` (tal como lo describe el enunciado, "auth: none") no es un
   valor reconocido por `@sap/cds` 9.6.1** — provoca el crash en producción
   `Error: Didn't find auth implementation for { kind: 'none', impl: '.../auth/undefined' }`.
   El valor correcto para desactivar la autenticación por completo es **`"dummy"`**:
   ```json
   "cds": {
     "requires": {
       "auth": "dummy",
       "[production]": { "auth": "dummy" }
     }
   }
   ```
   Sin el override específico de `[production]`, el perfil de producción seguía cayendo en
   `kind: 'jwt'` (por defecto de CAP cuando detecta un entorno productivo), y como el enunciado
   pide explícitamente **no** enlazar XSUAA, la app crasheaba en bucle al arrancar.
6. **Bug de tipos con SAP HANA en producción:** el driver `@cap-js/hana` devuelve los campos
   `Decimal` como **string**, a diferencia de SQLite (local), que los devuelve como `number`.
   El handler original (`sum + pkg.weight`) funcionaba perfecto en local pero en producción
   hacía **concatenación de texto** en vez de suma (`0 + "10.00"` → `"010.00"`, luego
   `"010.00" + "5.50"` → `"010.005.50"`), lo que además rompía `shippingFee` (`NaN` → `null` en
   el JSON). **Solución:** forzar conversión explícita con `Number(pkg.weight || 0)` en el
   `reduce`. Esto es fácil de pasar por alto porque las pruebas locales (SQLite) no lo
   detectan — **probar siempre también contra el endpoint desplegado en producción**, no solo
   en local.
