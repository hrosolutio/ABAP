## Hallazgos / desviaciones respecto a la guía genérica

Estos son casos reales encontrados durante el examen donde el nombre de campo o el
comportamiento del wizard no coincidía con lo asumido en la guía genérica de `src/` — quedan
aquí documentados para no repetir el tiempo perdido en un futuro intento:

- **Tarea 3:** el campo de tipo de avión en `ZI_CABAPD_PASSENGER` se llama **`PlaneTypeId`**,
  no `PlaneType`.
- **Tarea 5:** el behavior definition generado usa **draft** (`with draft; extensible;`), la
  clase de implementación se llama **`ZBP_R_Z7335TRAVEL`** (no `ZBP_ZZ7335TRAVEL`), y el alias
  de entidad es **`ZrZ7335travel`**. El tipo derivado para `MODIFY ENTITIES` debe declararse
  con el **nombre de la vista** (`TYPE TABLE FOR UPDATE zr_z7335travel`), no con el alias —
  usar el alias ahí da el error *"is not an entity for which BEHAVIOR can be defined"*.
- **Tarea 6:** el campo expuesto por `Z7335_AGENCY` es **`AgencyId`** (alias CDS), no
  `agency_id` (nombre de columna origen en `/dmo/agency`).
- **Tarea 8:** `/DMO/CUSTOMER.country_code` usa el data element estándar **`land1`**, no uno
  `/dmo/...`. El editor de Table Type en esta versión de ADT es un **formulario**, no
  código fuente: para definir la clave hay que poner `Key Definition = Key Component` (no
  `Standard Key`, que marca automáticamente todos los campos carácter) y añadir el componente
  manualmente seleccionando `<Primary Key>` antes de pulsar `+`.
